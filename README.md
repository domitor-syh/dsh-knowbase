# dsh-knowbase

[![CI](https://github.com/domitor-syh/dsh-knowbase/actions/workflows/ci.yml/badge.svg)](https://github.com/domitor-syh/dsh-knowbase/actions/workflows/ci.yml)

> dsh 知识库插件：资料留在本机、检索在本机执行、回答带出处
> A native, local-first knowledge base plugin for DeepSeek Harness

面向 **DeepSeek Harness（dsh）** 的原生知识库插件。在 dsh 内提供完整的「资料入库 → 自动检索 → 引用回答」闭环：**不依赖外部知识库服务、不调用云端模型、不修改宿主核心**。

- 目标宿主：Windows 桌面版 **dsh 0.2.0-rc.2**（官方标签 `dsh-v0.2.0-rc.2`），`dsh.engines` 声明 `>=0.2.0-rc.2 <0.3.0-0`；**0.2.1-rc.2 上已实测通过**。从 0.2.1 起宿主优先按 `engines.dsh` 判定插件兼容性，比较时**包含预发布版本**（`semver.satisfies(..., { includePrerelease: true })`），所以 `0.2.1-rc.2` 落在该范围内，而 `0.3.0-rc.1` 不会。
- 当前版本：**0.1.0**（MVP 范围已全部实现，发布前五项验收通过）。
- 技术路线：dsh 原生 Host + Client 插件（TypeScript）+ 本地检索引擎。

---

## 它做什么

### 入库：库就是一个文件夹

**库 = `$DSH_HOME/knowbase/` 下的一个文件夹**，库里的文件就是库内容。

- 在知识库页面「上传文件…」，或**直接用资源管理器把文件丢进库文件夹**，再点「重扫」——外部丢入的文件会被采纳。
- 外部**改名**会被跟随、外部**删除**会被丢弃。磁盘是资料的唯一真相。
- 删除资料 = 把它**移进 `<库根>/_回收站/`**，不销毁。想恢复就在资源管理器里拖回去（插件不提供回收站面板，这是刻意的）。
- 同名文件自动编号（`说明书 (2).pdf`），两份都保住。

支持格式与上限：

| 格式 | 处理方式 | 上限 |
|---|---|---|
| UTF-8 纯文本（下列扩展名） | 严格解码后切分索引，不执行代码或解析配置 | 2 MiB（2,097,152 字节） |
| 文本型 PDF | worker 线程抽取文字，**页码写进引用定位** | 20 MB、100 页 |
| PNG / JPG | **本地中英 OCR**（Tesseract，零云调用） | 20 MB |
| 其它格式 | 列表里如实标注「不可检索」并给出原因 | — |

文本白名单（大小写不敏感）：`txt md markdown text json jsonl yaml yml csv tsv js jsx mjs cjs ts tsx py rb go rs java c h cpp hpp cs css scss html htm xml sql sh ps1`。无扩展名、其它扩展名（含 DOCX、压缩包、SVG 等）仍只列出，不自动猜格式。

所有白名单文本须为**有效 UTF-8**（允许 UTF-8 BOM），允许 TAB/LF/CR；NUL、其它 C0、DEL/C1 控制字符会拒绝入索引。UTF-16、GBK 等不自动转码，请转换为 UTF-8 后重扫。旧 TXT/Markdown 也使用同一严格校验，不再把无效字节替换成乱码后索引。格式错误的 JSON/YAML 仍是可索引原文；新增源码/配置格式不解释 Markdown 标题，`# ` 开头的合法注释也保留为检索正文。不会验证语法、执行 JS/Python/脚本、解析 HTML 或加载其外部资源，阅读器按纯文本显示。白名单和编码/控制字符校验不是通用二进制鉴别：完全由可打印 UTF-8 组成的字节流无法与文本区分。2 MiB 上限同时检查扫描信息与实际读入字节，扫描后增长的文件也会拒绝。

加密 PDF、扫描件（无文字层）、超页、超大文件各有独立文案，不会静默失败。库文件夹递归扫描上限 8 层。

**重扫默认是增量的。** 当前宿主运行期间会按相对路径、文件大小和修改时间复用未变化资料；上传覆盖会显式失效对应路径。若外部程序在文件大小和修改时间都不变时改写内容，请使用 `/kb rescan --force`。这份复用快照只存在于当前服务进程，重启后会重新建立。

每个知识库会保留最近一次**已完成**扫描的只读报告，页面下方辅助区和 `/kb rescan [--force]` 命令共用这份报告。页面中的完整报告与 OCR 区块并列，窄屏依次排列；原有失败明细仍按需展开，文件行也保留不可检索原因。报告包含扫描文件数、增量新增/复用/变化/删除、重建尝试、格式跳过、不可检索数量和耗时；不可检索明细最多展示 100 个相对文件名及固定原因，超出部分只显示数量。格式跳过统计不支持的常规文件，可能与复用同时出现；重建尝试包含失败、空文件、超限和 OCR 未就绪等情况。扫描中断时旧快照继续可用，多库扫描可能已完成前面的库。内部绝对路径和原始异常不会进入报告、页面或命令输出；报告仅存在运行时内存，重启后重新建立。

### 检索：中文 n-gram + BM25，不走向量

- **不使用 embedding / 向量库 / 重排模型**，因此不需要 API key、不需要联网、也没有索引重建的等待。
- 中文按字符 n-gram 建索引，并用独立 code-point posting 支持单汉字（包括扩展区汉字）；单汉字不加入普通 n-gram 长度与词频统计。
- **含数字的词整词 + n-gram 双写**，支持编号片段；NFKC 后至少 4 字符、含数字且不含汉字的纯字母数字查询，还必须连续存在于同一个编号串。`6353` 可命中 `13363537216`，`6353999` 不会仅因共享部分 gram 而命中。2–3 字符短片段保留旧召回，仍可能偶然命中；混合、多词和带标点查询保留 OR 语义，不保证全部词同时匹配。`ABC-1234` / `ABC 1234` 不会被拼接成 `ABC1234`。
- 纯拉丁词只做整词匹配（`port` 不会命中 `ports`）。
- **资料标题进索引**，库名不进（否则该库每条片段都会命中库名）。
- 调用方传入范围时，长度均值与 IDF 只统计该范围；未选中的库不影响当前结果分数。排序后、截断前按同库同资料的 NFKC/空白归一化正文去重，不合并不同资料或不同库的出处，也不重写引用原文。
- `pnpm benchmark:retrieval` 运行纯内存合成语料（10 个已选文件 + 1 个范围外文件，26 问、top 3）。O-04 对照由 20/26 到 26/26，MRR@3 / mean Recall@3 由 8/9 到 1，负例准确率由 5/8 到 1；这是小型回归基准，不是生产准确率或规模性能测量。详见 [O-04 验收报告](<outputs/O-04-检索质量验收.md>)；源码仓库保留完整逐例结果与隔离旧实现复现树，安装包不含这些开发产物。
- 排序与机器无关：`src/core/order.ts` 用 `Intl.Collator('zh-Hans-CN')` 钉死拼音序，判等退码位；CI 有一条「模拟非中文机器」的测试配置守这条。

### 对话：模型请求前注入证据，回答带出处

- 输入区有「知识库」药丸按钮 + 选库弹层（搜索框、每库一个开关、页脚「全部开启 · 全部关闭」与开启计数）。**开关本身就是「是否使用」**——一个都没开就不使用知识库，按钮不显蓝色。
- 选择**按会话持久化**，宿主重启后保留。新会话默认关闭知识库，不继承其他会话的开启状态或勾选范围；需要时由用户在当前会话手动开启并选择库。当前不设置 workspace 项目默认范围，因此不会因项目或工作区自动改变会话选择。
- 命中后，回答操作条出现「N 知识库来源」按钮；点开可按来源文件筛选、展开/折叠片段，筛选保留回答原有 `[n]` 编号。每条可「在右栏打开」，读取最近扫描的资料并定位；面板保留当时检索原文，不能据此恢复旧版文件。
- 每条可「复制引用」：包含库名、文件名、locator 与稳定引用 ID；不复制 `filePath`、资料 ID 或原文正文，并隐藏展示标签中可识别的绝对路径。剪贴板不可用或失败会显示可手动复制的文本。正文中原有路径仍作为证据显示，不承诺通用秘密识别。
- 新引用 ID 是 `kb-cite-v1-` 加 SHA-256，基于库 ID、资料相对身份、chunk ordinal、locator 和精确正文；相同证据跨查询排名和强制重扫稳定，不依赖绝对库位置、展示名或 revision。资料改名/移动、分块定位或内容改变时 ID 可变，不是永久文件身份或历史存储。旧消息继续显示与复制已有出处，不伪造稳定 ID；同名旧来源缺少身份时只能按库名和文件名归组。
- 引用弹层使用宿主主题与中英 locale，支持 Escape、键盘焦点约束和关闭后焦点恢复。
- 没命中时给固定文案徽标，区分五种情形：**未命中 / 空库 / 未勾选 / 库失效 / 检索失败**。检索失败会说明原因，而不是编一个答案。

### Agent 工具：读取、统计和新文件提案

| 工具 | 用途 | 默认 / 上限 |
|---|---|---|
| `kb_list` | 不传 `kbId` 列当前会话选中的库；传 `kbId` 列该库资料 | 50 / 100 条，支持 `offset` 分页 |
| `kb_search` | 在当前选择内检索；可用 `kbId` 进一步缩小范围 | 6 / 8 个片段，每段最多 1200 字符 |
| `kb_read` | 用 `kbId` + `materialId` 读取提取正文 | 4000 / 8000 个 UTF-16 代码单元，按 `nextOffset` 续读 |
| `kb_stats` | 查看当前选择内的自动召回计数与资料召回轮次 | 50 / 50 份资料，支持 `offset` 分页；默认不记录 |
| `kb_propose_text` | 创建新的 UTF-8 文本资料提案，等待用户在输入区预览和批准 | 64 KiB、单一安全文件名；不能覆盖、删除或改名 |

读取与统计工具始终检查**调用会话**的知识库开关与选择，不接受会话 ID、任意路径、写入或删除参数。关闭、未勾选、库失效、初始化中、无匹配与读取失败分别返回结构化状态；缺少调用会话时拒绝读取。搜索结果包含库/资料 ID、locator、排名诊断、索引版本和内部阅读地址，不返回宿主绝对路径。

`kb_propose_text` 只保存待审提案，不写入知识库文件或刷新索引。用户可以在会话输入区查看、批准或拒绝；Agent 没有批准入口。批准时会重新检查会话范围、提案有效期、知识库 revision 和同名文件，失效或冲突的提案拒绝应用。

工具读取**最近一次成功扫描的内存快照**，不会触发重扫、OCR、语言包下载或实时磁盘读取；外部文件变化需先重扫。`kb_read` 返回提取正文，不是原文件字节，也不承诺与原文件行号一致。资料内容仅作为证据，不作为指令。工具 schema 可被宿主发现，但不会额外注入完整库地图到 system prompt。宿主缺少 tools 服务时，其他功能保持可用。

在当前 Host 提供 `systemPrompt.section()` 时，插件还会注入一段有界的知识库概览：只包含库名、描述和资料/可检索数量，不包含正文、库路径或原始异常。元数据会被标记为插件生成的信息而非用户指令，并限制总长度；没有知识库或 systemPrompt 服务不可用时不注入内容。需要实际证据仍应调用 `kb_list`、`kb_search` 或 `kb_read`，概览不会替代会话范围检查。

### 本地自动检索统计

「自动检索统计」作为可选诊断，入口位于 **插件管理 → 本知识库插件的详情页**，默认折叠；知识库主页面不再放置统计区块。需要排查召回情况时，再展开并手动开启「记录自动检索统计」。默认关闭，保留最近 30 个本地日历日；只保存日期、知识库/资料身份与计数，不保存问题、正文或回答。启动、查询、新召回与运行中的跨日维护会裁剪过期数据；插件未运行时待下次启动清理。统计面板仅在展开或手动刷新时请求数据，不轮询。

统计包括请求、命中、未命中、未就绪、范围失效、异常，以及每份资料被召回的轮次。命中率为 `命中 / (命中 + 未命中)`，不等于答案正确率；一轮同一资料命中多个片段只计一次，手动检索测试和 Agent 工具调用不计入。无可归属知识库范围的启动未就绪、关闭和未选择不计请求。

运行期去重键有容量上限，重启重放或键被淘汰后可能重复计数。资料按现有相对身份统计，改名后作为新身份；UI 会清理已删除资料的统计。`kb_stats` 仅展示当前会话可见资料，多库请求总计只在该请求的全部库都属于当前范围时计入，不能把跨库请求拆成每库一次。

统计失败不会中断检索或改变 BM25 排序；未保存/丢弃的统计有单独提示，重启后可能丢失。用户可关闭后查看保留期内历史，或确认「清空统计」；开关和清空仅供用户操作，清空不影响知识库资料。当前不生成摩擦系数或资料质量评分，也未增加已有资料的正文编辑功能。

### 知识库页面：侧栏图标 + 中央列独立页面

与「插件管理」「定时任务」并列在侧栏。页面采用宽留白和扁平区段：页头保留「添加知识库」操作，下方是通栏检索工具条，再下方为左侧知识库列表、右侧当前库文件。扫描报告与 OCR 位于主区下方的辅助区，窄屏依次排列。

现有操作保持原样：建库 / 改名 / 描述 / 删库；上传文件、查看索引片段、重扫全部；「从文件资源管理器打开」库文件夹；OCR 的**检测 / 下载语言包 / 进度 / 取消**；检索测试仍可选择范围、查看命中的 score 与覆盖率，不调用模型。文件行保留不可检索原因和需要时的 OCR 提示；完整扫描报告及其原有失败明细展开方式不变。自动检索统计仍在插件管理详情中按需查看。

文件大小左侧常驻显示扫描结果图标：绿色勾圆「可检索」、中性横线圆「格式不支持」、警告三角「不可检索」；悬停可查看说明和失败原因，可检索仅表示已提取文字。没有扫描结果的旧 Host 不显示图标。上传会先扫描新文件再刷新列表，失败或空文件也会显示相应结果；通过资源管理器加入/修改资料后需重扫。页面「重扫」与「重扫全部」会强制重新解析并刷新所有扫描结果，包括保留大小/修改时间的外部修改；PDF、图片较多时会更慢。后台其他增量扫描仍可复用未变化文件。文件操作与滚动条之间留有间距，主区底线与两栏竖线相接。

知识库选中与悬停使用相同的中性底色，名称保持普通颜色和字重；标题与说明字号对齐官方插件页，添加按钮采用截图中的中性反色与圆角，文件行保持紧凑。检索结果以搜索框下方的独立浮层显示，不挤动资料主区；背景与范围按钮同色，深色模式浅字、日间模式白底深字。默认阅读区按文件名、来源位置、原文片段排列，score 与覆盖率在「检索详情」中按需展开。右上角关闭按钮或 Escape 可收起并返回输入框，长内容在浮层内滚动，调整窗口或滚动页面时跟随搜索框。输入区知识库按钮的关闭、开启及数量标签共用固定行盒。原有菜单、资料操作、范围选择和应用明暗主题继续保留。

## 安装

```bash
# 打包（在仓库根目录）
pnpm install
pnpm build
pnpm pack            # 产出 domitor-syh-dsh-knowbase-0.1.0.tgz
```

```bash
# 装进一个 dsh profile
dsh plugin --profile <profile> add /绝对路径/domitor-syh-dsh-knowbase-0.1.0.tgz
```

三个容易踩的点：

1. **`dsh plugin add` 的 tarball 必须给绝对路径。** 裸相对名会被当成 npm 包名去 registry 找，报 404。
2. **想装进隔离环境就先设 `DSH_HOME`。** 漏了它，命令会「在别处成功」——报 `Done` 但目标目录什么都不长，实际装到了真实的 `~/.dsh`。
3. **同版本替换应通过官方插件管理器处理。** 先检查安装结果；如仍复用旧产物，用管理器移除再安装该 bundle，并核对安装副本哈希。不要手删 profile 的 `node_modules`、锁文件或修改 profile 配置。文件替换完成也不代表宿主已加载新模块，必要时按管理器提示重启。

**OCR 引擎已编进产物**（`lib/ocr-runtime.cjs` + `lib/ocr-worker.cjs` + 3 个 wasm），`tesseract.js` 不是发布依赖 ⇒ **全新 profile 首装零手工步骤**，不需要 `allowBuilds`。

**OCR 语言包首次使用时下载**（中英共约 4.5 MB），也可以提前在知识库页面的「图片文字识别」里点「下载语言包」。检测只做两次 `stat`、不联网；下载可取消，取消会删掉本次已落盘的文件。**资源到位后识别全程零网络请求。**

## 使用

1. 点侧栏的「知识库」图标，新建一个库。
2. 上传文件（或把文件丢进库文件夹后点「重扫」）。
3. 回到对话，点输入区的「知识库」药丸，打开要用到的库。
4. 提问。回答下方出现「N 知识库来源」，点开可核对出处、在右栏读原文。

命令行也能管理库（`/kb` 系列，用户后续可能移除）：

```
/kb help
/kb list                                   # 列出知识库与文件数
/kb files <库名>                            # 列出库内的文件
/kb create <名称>                           # 新建知识库（同时建好它的文件夹）
/kb rename <旧名> :: <新名>                  # 重命名（文件夹一起改名）
/kb delete <名称>                           # 删除知识库（文件夹移入 _回收站，不销毁）
/kb rm <库名> :: <文件名>                     # 删除文件（移入 _回收站，不销毁）
/kb rescan [--force] [库名]                 # 增量重扫；--force 强制重新解析全部文件
/kb use <库名[,库名]|全部|关闭>               # 设置本会话的检索范围
/kb search <问题>                           # 检索测试（不调用模型）
/kb root                                    # 显示知识库根目录（文件实际存放的位置）
```

## 数据在哪，边界在哪

| 内容 | 位置 |
|---|---|
| 库记录、会话选择 | `$DSH_HOME/storages/`（宿主 `storageDomain`：`dsh_knowbase` / `dsh_knowbase_sessions`） |
| 资料文件 | `$DSH_HOME/knowbase/<库名>--<库 id>/` |
| 删除的资料 | `$DSH_HOME/knowbase/_回收站/` |
| OCR 语言包 | `$DSH_HOME/knowbase/.ocr/` |

**⚠ 库根目录在 `$DSH_HOME` 下 ⇒ 只在本地宿主有效。** 远程 / 云宿主下该目录不存在或不可写，插件会明确报错而不是静默丢数据。

**外部删除库文件夹的处理取决于同步时机。** 运行期间执行「重扫全部」时，已经消失的库文件夹会使对应库记录与内存索引被移除；启动初始化则先为尚有存储记录的库补建缺失文件夹，再同步磁盘。不要把直接删除文件夹当成可靠的删库入口：请走页面删除或 `/kb delete`，把资料安全移入回收站。库内资料始终以磁盘文件为准。

**文件系统安全边界。** 根目录本身不能是符号链接或 junction；根目录以下不跟随任何链接，列表将其标成 `other`，读写和经由链接祖先的操作会被拒绝。目录移动/删除前也检查整棵树，拒绝夹带链接或特殊文件；socket/FIFO/设备节点等不作为普通文件读写。配置根目录以上的链接祖先属于受信安装路径，以解析后的真实根目录为物理边界。此检查不承诺消除外部进程竞态（TOCTOU）或硬链接风险。

**索引版本是运行期审计标记，不是跨重启内容哈希。** 同一次扫描提交发生新增、删除、资料状态变化或库名/路径身份变化时递增一次；无变化扫描及同内容强制重建不递增。快照和 chunks 不持久化，因此不能据此审计停机期间所有文件改动。

**整个库文件夹拷走就是完整备份。** 没有 JSON 中间层，也没有单独的导出功能——这是文件模型的直接结果。

## 设计取舍（有意为之，不是没做）

| 取舍 | 原因 |
|---|---|
| 关键词检索，不走向量 | 本地、零依赖、零联网、改完文件立刻可搜；换来的是不理解同义改写 |
| 不做回收站面板 | 删除即搬家，恢复交给资源管理器；少一套要保持一致的状态 |
| 不做重复检测 | 撞名自动编号即可，两份都保住比「拦住用户」更少摩擦 |
| 阅读器只读 | 它的职责是「看见证据」，多一个写入面就多一条要保持一致的路径 |
| 不切宿主官方预览 | 官方预览对 Markdown 的源码行导航不可用，而引用最常落在 `.md` 上 |
| 不做「检索中」徽标 | 检索发生在模型请求之前，宿主没有把这个瞬间作为可订阅状态暴露出来；假转圈会把「检索」和「生成」混成一段，比不做更误导 |
| 不提供对话区的「管理知识库」快捷入口 | 被宿主 API 挡住：设置面板的开关状态是闭包 store，未作为服务发布 |

### 在隔离宿主里验证

**有数据写入的开发探针默认使用隔离 profile。** 用户明确授权后，可以通过当前宿主的官方插件管理器更新 `desktop` 中已安装的插件；这不授权写入/删除真实知识库夹具，不手改 profile 文件，也不使用 CLI 绕过桌面独占限制。独立开发宿主可使用单独的 `DSH_HOME` 与 profile：

```bash
export DSH_HOME=$PWD/.dshdev
dsh --profile kbdev --from-default-profile web
dsh plugin --profile kbdev add /绝对路径/domitor-syh-dsh-knowbase-0.1.0.tgz
dsh --profile kbdev --no-open --port 3111
```

`dsh plugin add` 会自动写进该 profile 的 `dsh.profile.bundles`，之后不需要 `--patch`。

**部署后必须核对哈希**：对比本地 `lib/client.js`、`lib/index.js` 与 `<profile>/node_modules/@domitor-syh/dsh-knowbase/lib/` 下的副本。验收物是**安装副本**，不是 profile 的 `package.json`（那只是声明）。

## 关键约束（改动前请先读）

以下均在目标宿主上实测确证，细节见 [HANDOFF.md](HANDOFF.md) 第 7 节。

- 只通过 dsh 官方 slots / Remote / Agent 接口接入，**不修改宿主核心、不用 DOM 注入绕过接口**。
- 目标版本**没有** `systemPrompt.refreshContext`，`PromptContext` 也**没有** `required`；上下文注入走 `agent/pre-step` waterfall，把证据消息追加进 `next()` 返回的决策。**`next()` 必须永远 await 并尊重其结果**——覆盖别人的 `reject` 等于悄悄重启一个已被停掉的步骤。
- Client↔Host 的业务通道是**自己接的类型化 Remote**：官方生成器对独立插件不可用，但产物本质只是 `zod schema + InvocationDescriptor[]`，手写即可（`src/client/contribution.ts`）。不能用装饰器；原型描述符里的 **`version: 1` 必须有**。方法清单的唯一来源是 `src/remote-methods.ts`。
- 浏览器半边**只能用宿主模块表里已有的包**：非宿主依赖必须内联（`zod`），且不能用自动 JSX 运行时（`jsx: "react"`）。
- **`inject` 里写不存在的服务名会让插件永久 pending 且零报错。** 只列已在目标宿主上确认存在的服务；可选服务（如 `theme`）必须用 `ctx.inject([...], scope => …)` 动态取。
- `desktop` profile 被 Electron 应用独占，CLI 无法驱动。
